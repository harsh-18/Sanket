Why you will not see “99% accurate” on this page

Speech accuracy is not one number. It moves with accent, mic, distance, noise, vocabulary and language. Published benchmarks put Hindi ASR at roughly 16% word error rate for the best cloud engine on read speech — about 84% word accuracy — and it drops sharply for spontaneous, noisy, code-mixed speech ( ASR benchmark for Indian languages ).

Sign-language papers quoting 99%+ are closed-set classification on one signer and a fixed vocabulary, not translation ( ISL detection , SURF+SVM ). That is exactly the claim shape Sanket uses: a constrained vocabulary, honest confidence, and a clarify step instead of a guess.

How Sanket works

Three layers, one conversation. Input, interpretation, output — chosen independently by each participant.

A · Input

  • Speech (hi-IN, en-IN)
  • ISL gloss cards (validated)
  • Experimental handshape camera
  • Text / assistive switch

B · Interpretation

  • Speech recognition + confidence
  • Language identification
  • Phrasebook translation (on-device demo)
  • Uncertainty → confirmation step

C · Output

  • Spoken audio (TTS, rate control)
  • Large text + screen readers
  • Haptic alerts
  • Per-recipient formatting

Recipient-specific output working
ISL: 12 validated gloss cards working, constrained
ISL: continuous translation / grammar not built — not claimed

Free-text translation between any language pair phrasebook only; backend needed
Braille output, emotion detection, signing avatars out of scope v1

3-minute judge demo script

  • Tab A (hearing, Hindi speaker): onboarding → Speak + Read + Hear.
  • Tab B (Deaf participant): onboarding → Sign + Read text only.
  • Both join room SANKET-42 .
  • A speaks: “मुझे डॉक्टर के पास जाना है” → B sees large text instantly, no audio forced on them.
  • B taps the “मदद” gloss → A hears “Help” spoken aloud and sees it as text.
  • Say something unclear → Sanket asks to confirm instead of sending a wrong message.
  • Open the Accuracy lab, read 3 sentences, show the measured number and explain what it depends on.

Deploying past this demo

App
React Native + Expo (TypeScript, Expo Router) → this UI maps 1:1.
API
FastAPI on Cloud Run: /session, /messages, /stt, /tts, /translate, /isl/recognise.
Data
Supabase Postgres + Auth + Realtime; RLS per room; no raw audio/video stored.
Speech
Google Cloud STT/TTS (hi-IN, en-IN) + native TTS fallback offline.
ISL
MediaPipe landmarks → PyTorch temporal model → confidence gate → human review.
Accuracy
Per-language WER tracked in CI with a checked-in test set, not a marketing number.

Known limits (say these out loud in Round 3)

  • Browser speech recognition needs HTTPS or localhost, and is unavailable in Firefox / most Safari versions.
  • Cross-device realtime needs the Supabase channel — this file uses same-browser tabs.
  • Translation of free text is a demo phrasebook; production uses an API with human review for medical/legal content.
  • Handshape camera is a heuristic; the validated path is the gloss vocabulary.
  • No raw video or audio is stored by this build. Nothing is sent to a server.
